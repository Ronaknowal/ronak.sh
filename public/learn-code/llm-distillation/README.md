# Knowledge distillation: complete executable packet

Eight new programs implement stable distribution losses/manual gradients,
finite sequence derivatives, arithmetic traces, a teacher, students, evaluation,
the prospective experiment driver, and an ordinary pretrained TRL route.
The packet also carries three exact prerequisite programs: TinyLM from Causal
Language Modeling, and response serialization/evaluation from SFT. Importing
the TinyLM module does not start its Alice demonstration.

## Environment and finite mechanisms

Use Python 3.12 in a virtual environment. The executed CPU environment used
NumPy 2.3.5, Torch 2.14.0+cpu, Transformers 5.19.0, TRL 1.14.2,
datasets 5.1.0 and accelerate 1.15.0. Install a platform-appropriate Torch build;
these are the recorded versions, not a promise that arbitrary versions match.

```sh
python -m venv .venv
python -m pip install numpy==2.3.5 torch==2.14.0 transformers==5.19.0 trl==1.14.2 datasets==5.1.0 accelerate==1.15.0
python distillation_loss.py --output loss-results.json
python distillation_sequences.py --output sequence-results.json
python distillation_traces.py --output trace-results.json
python distillation_evaluate.py --verify --output evaluation-checks.json
```

Activate `.venv` before installing/running (`.venv\Scripts\Activate.ps1` on
Windows; `source .venv/bin/activate` on POSIX). The four commands perform finite
mechanism checks. They do not fit a scientific model. Loss checks compare manual
NumPy gradients, finite differences and PyTorch; sequence checks separately
compare full-visitation and detached-prefix derivatives.

## Run a new arithmetic campaign

```sh
python distillation_study.py freeze --work my-study
python distillation_study.py run --work my-study
```

Use a new work directory for a new experiment. Freeze writes the entire recipe,
source hashes, family splits, token vocabulary and batch plans before fitting.
Run executes one 1,200-update teacher, one 256-candidate collection and all 15
600-update student fits, then seals selection before heldout evaluation. It
reuses completed stages and resumes incomplete optimizer/RNG checkpoints.
Do not edit frozen source or delete outcomes to obtain a nicer result.
The included `results/arithmetic` directory supplies the recorded protocol,
candidate ledger, complete evaluations, selected tiny weight files and terminal
histories for inspection. It omits optimizer resume files: it is an evidence
packet, not a directory intended to resume the original campaign.

The vocabulary contains 121 events and is entirely generated by
`distillation_traces.py`. No external corpus is needed. The full teacher has
117,120 parameters, student 21,408. The task is deliberately small; the recorded
teacher got 0/28 held-out test answers correct despite producing valid traces.
Every seed and invalid result remains included. This is not an R1 reproduction.

## Ordinary pretrained route

The native program accepts local paths and never silently downloads a model.
The required base is EleutherAI/pythia-14m revision
`cf967c0a9a04383db6f7b1108d86b2962634b4ac` (Apache-2.0). The included
`acquire_model.py` and `model-source-report.json` are exact copies of the SFT
input utility; they download/check the six pinned public model/tokenizer/card
files, about 30 MB, and preserve mismatching existing files for inspection.

The teacher is the response-only seed 17 selected checkpoint from the complete
[SFT packet](../supervised-fine-tuning/README.md), produced by that packet's
prospectively specified run. We do not redistribute adapted pretrained weights.
Its `model.safetensors` SHA256 is
`8ffe40fc676d22d608b58b35af11bf467c36981dbb3ccfe373a7d574bd8251cd`.
The program requires this identity for the recorded recipe. Reproduction on
another platform can produce different floating-point weights; a deliberately
new teacher is a new experiment: change the explicit `TEACHER_SHA` contract
before preflight/freeze, record its provenance and do not claim it reproduced
the recorded teacher. Never replace a teacher after viewing student outcomes.

```sh
python acquire_model.py --output base
python distillation_native.py preflight --base base --teacher TEACHER --data data --work native-study
python distillation_native.py freeze --base base --teacher TEACHER --data data --work native-study
python distillation_native.py run --base base --teacher TEACHER --data data --work native-study
```

Replace TEACHER with the actual selected SFT directory. Preflight performs no
sampling or optimization. The program keeps copied blocks 0/2/4 and renumbers
their cache metadata 0/1/2 without changing their tensors. The native route
performs 24 offline CE and 24 on-policy full-vocabulary KL updates from the same
initial student, then evaluates all 105 development / 104 test examples once.
Its prompt-only on-policy dataset does not use human labels as teacher targets.
The included native receipts retain an initial cache-address failure before
the first on-policy generated batch, its fixed-token precision checks and a
source-guarded continuation. The already-complete offline 24 updates and teacher
corpus were reused exactly; the original protocol remains preserved.

Data are unchanged Poem Sentiment TSVs from revision
`612e9a1f86799126c68f0c5d9c3f1fc28f88068f` of
[google-research-datasets/poem-sentiment](https://github.com/google-research-datasets/poem-sentiment),
licensed [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Credit Emily Sheng and David Uthus, *Investigating Societal Biases in a Poetry
Composition System* (2020), <https://arxiv.org/abs/2011.02686>.
The original TSV bytes are retained; `sft_data.py` excludes mixed training
labels and implements the exact original 843/105/104 retained split.

## Read the programs in dependency order

1. `distillation_loss.py`: stable log-softmax, three divergences, explicit
   gradients, masks, temperature scaling and hard/soft mixing.
2. `distillation_sequences.py`: four-leaf enumeration, local/visitation
   derivatives, seeded positive-support sampling and exact expected CE.
3. `distillation_traces.py`: 121-event vocabulary, family split, parser/checker,
   shifted target mask and each recipe's candidate eligibility.
4. `distillation_teacher.py`: teacher selection and once-only candidate ledger.
5. `distillation_student.py`: same-seed initialization, matched exposure plans,
   response objectives, optimizer checkpoints and earliest-tie selection.
6. `distillation_evaluate.py`: actual length-based generation and separate
   grammar, arithmetic, reference NLL and teacher agreement measures.
7. `distillation_study.py`: prospective source/data/settings guards and the
   all-terminal selection seal before heldout scoring.
8. `distillation_native.py`: pretrained model identity, tokenizer-event guards,
   full/chunk parity, ordinary TRL training and separate evaluation modes.

`tiny_causal_lm.py` supplies the already-taught explicit attention/block/head
architecture. `sft_data.py` and `sft_evaluate.py` retain the inspected SFT
serialization, EOS masks, full-vocabulary greedy generation and complete-label
candidate scoring. The thin base-file acquirer is an input helper.

All result tables are observations from the supplied immutable receipts.
Generated text is data for inspection; no generated code is executed. Comparing
offline versus on-policy changes more than one factor. Runtime and parameter
counts are not measured serving speedups, and teacher agreement is not accuracy.
