## Purpose, observable outcomes and route

The unifying question is: what information does a model receive when a recorded table becomes numerical coordinates, and which observations are allowed to determine that conversion? The foundational object is a row-by-feature table with units, types and missingness, the fitted transformation state, and the resulting feature matrix. Draw those objects before distance contours, dependency diagrams or performance bars.

## Continuous entities, notation and colour

Begin with source row309: bill length51.0mm, bill depth18.8mm, flipper length203.0mm, mass4100g, recorded sex `male`, target species `Chinstrap`. Row309 is a zero-based file position, not an animal identifier. Show a second explicitly **altered copy** with missing mass while keeping recorded sex, and a constructed unknown value only as an input-policy example, not a new biological category.

Keep measurements in rows, features in columns. `X` is n×d; `y` is a separate target vector; mask `M[i,j]=1` means a value was absent in the input (this is opposite to some statistical response-indicator conventions, so announce the conversion before MAR notation). The fitted object stores permitted-row medians, centres/scales, category order and later transform-specific parameters. Numeric output may be negative without implying negative physical mass. Train/new-row roles have labels and different boundary marks; output position is meaningful and immutable under a new record.

Use direct identities throughout: Q amber outline/current focus, A blue triangle, B rose square; neutral measurements and result coordinates. For nominal categories use blue/rose/violet with labels/shapes, not decorative green/olive. Missing is a hatched empty cell with `NA`, filled estimates keep hatching/outline plus their numerical value, observed values remain solid. Group/split identities use line/dash patterns and labels independent of category identity. Magnitude uses a declared sequential/diverging scale with units; current selection is an outline, not an identity recolour. Charts and matrix cells share identities when linked.

Introduce new constructed fixtures explicitly: Q/A/B metric rows; five-value `[1,2,3,4,100]`; simple-imputation `[10,20,NA,NA]`; D1–D3 donor matrix; A/B/C six-row targets/folds; univariate nonlinear landmarks; a small masked two-column regression table. These are exact pedagogical constructions, not measured ecological experiments or observed performance. Every switch states what remains fixed and why a different object is needed.

## Specialist completeness and deliberate boundaries

Local specialist coverage includes population versus sample spread, monotone tree qualifications, penalty/geometry effects, sparse centring, constant/empty columns, schema stability, reference coding/rank, rare/novel policies, conditional missingness, donor overlap/target eligibility, robust tie/fallback rules, nonlinear map domains/likelihood/ties/endpoints, basis capacity/local support/extrapolation, cyclic semantics, regularized target encoding with group/time chronology, signed hashing collisions, iterative fit/inference separation, proper-MI versus deterministic prediction, pooling variance and MNAR sensitivity. These are not merely names in a reference table.

Deliberate boundaries: no universal optimal scaler or imputer; no new performance leaderboard; no automatic MNAR identification; no general causal missing-data identification theorem; no exhaustive contrast family, multilevel MI or full survey weighting implementation; no learned embeddings/autoencoder training (owned by later representation lessons); no full NLP tokenizer/TF-IDF implementation (link the text-feature owner when an actual exact source is available, otherwise use explicitly given bags); no full nested-CV/search reconstruction (next lesson). Natural cubic splines receive a visible comparison and reference, while the computational promise here is B-splines. Native categorical tree behavior is implementation-specific and receives an ordinary current-doc alternative, not a fake generic ordinal-code equivalence.

Current practice directions: explicit fitted schemas/feature names, sparse outputs, train-only rare maps, target-aware splitting, native missing/category support and multiple-imputation diagnostics. These are maintained API/design practices, not a frontier benchmark claim. No extra topic or application is needed; the retained real penguin application plus constructed counterexamples teach distinct mechanisms without a second dataset campaign.
