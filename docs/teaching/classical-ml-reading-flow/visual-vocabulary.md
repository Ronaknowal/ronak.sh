# Classical Machine Learning: visual vocabulary

This module contract governs new reading-flow designs. It composes with each
topic's explicit local entity/colour legend; it does not retroactively certify or
recolour accepted lessons. The neutral charcoal and amber site theme remains.

## Draw the object and preserve its identity

An observation is a labelled point or an identified row of feature cells. Put
its ID outside the feature bracket: IDs, reference annotations and future outcomes
must not silently become fitting coordinates. Draw coordinate axes at equal
aspect when a geometric length or angle is being interpreted. A feature array,
distance/Gram array or contingency table has aligned cells and declared row and
column roles, not a paragraph inside a rectangle.

A query has a diamond or another locally declared shape distinct from a
reference observation. A representative/center has a cross or similarly distinct
glyph and its own ID. Trees have real branches, node/leaf relationships and
terminal IDs/counts. A node glyph is an algorithm object; a sentence card joined
to another card is not a mechanism drawing. Coefficients and normalized masses
may be columns on a labelled numeric scale. Time-based observations sit on a
time axis with sampling gaps and explicit inclusive/exclusive boundaries.

Each topic declares its local mapping before it is used. Keep that mapping
through related pictures, edits, reordering and resets. Reuse the earlier
topic's object/notation when building on it, or explain the deliberate change.
Do not replace distinct partitions, classes, channels or reference/query roles
with indistinguishable neutral marks for visual uniformity.

## Colour carries a declared relationship

Use distinct accessible colours for the entities or memberships being compared,
with IDs/shapes/labels as redundant cues. Blue, rose, violet, cyan and peach are
available semantic choices; this is not a compulsory five-class palette.
Do not introduce green/olive decoration. Preserve useful established local
encodings rather than imposing the same bin hues on unrelated examples.

Amber normally marks focus or a learner action. Some retained topic vocabularies
use an amber query diamond and a white focus outline; keep that explicit local
convention instead of assigning both meanings to an unlabeled mark. A proposed
topic may use a plum query diamond and amber focus. These are declared local
bindings of the same reference/query/focus roles, not permission for arbitrary
colour changes between connected figures. A score crossing a threshold cannot
recolour a query into a verified fault or class without actual label evidence.

Nominal group IDs are names, not geometric distances. A pure renaming keeps the
same group correspondence and colours. In nonequivalent partitions name each
panel's actual groups. Quantitative colour needs an adjacent labelled scale,
units and baseline. Reference annotations stay in a separately labelled lane.

## Lines describe operations

An assignment edge ends at the representative actually used. A residual has
its coordinate difference and length/squared contribution labelled. A directed
neighbour relation identifies which endpoint owns the radius or statistic;
do not turn a directed maximum into an unlabeled symmetric link. A tree-path
highlight follows the stored inequalities and counts edges, not nodes.

A dataflow arrow names what travels: a row, an index, a scalar, fitted state or
a coefficient contribution. Fitting and query arrows have different roles;
future records and annotations do not feed preprocessing unless that information
is legitimately available under the declared task. If a view is a projection,
label the scoring geometry separately. A fitted boundary is not a probability
contour without the probabilistic model that would justify that interpretation.

## Inline teaching and live changes

For each new mechanism: connected question, one-line lead, actual picture,
walkthrough of its labelled parts and worked operands, then equation/code.
Use the shared `lesson-flow` surface and LessonFlow primitives. Pictures and
labs stay in the text without card frames, banners or separate lab headings.
Specialist depth remains visible and receives the same careful explanation.

Each local investigation has one to three already-taught changing quantities,
directly below its visual, and a live result sentence. Natural Step/Back/Reset
actions may trace a process; name exactly what they advance and keep the controls
small. Do not collect the whole lesson's parameters into an advanced grid, a
preset wall or a display-mode dashboard. Split different causal questions into
successive local investigations. A scientific choice such as batch-versus-novelty
changes the task and requires its own taught operands; it is not a generic view
mode that excuses hidden explanation. There are no learner prediction gates.

Exact values, measured outputs and hypothetical illustrations are labelled by
their actual provenance. Draw reachable algorithm states for mechanism examples;
an arbitrary arithmetic normalizer cannot masquerade as a fitted sample-size
correction. Review default, meaningful changed, null/boundary and error states.
At narrow and enlarged-text layouts, recompose the figure and labels rather than
shrinking an entire SVG. Source checks and bounds checks do not substitute for
personal reading of actual rendered diagrams. Changes to this contract require
explicit cross-topic disposition, not silent changes in each author branch.
