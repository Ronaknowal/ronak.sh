## Algorithm and dependency cost contracts

P04 naive prediction sorts m training distances per q query: O(q m(d+log m)) time, O(m d+q k) state/output if processed rowwise; the retained P01 broadcasts a held×train distance matrix, O(qm) working memory in one dimension. Teach this distinction rather than calling either globally optimized. Mixed preprocessing computes fitted medians/sorted vocabulary O(n d log n + n v) for a transparent implementation, transforms O(n(d+v)); state includes dimension/vocabulary and cannot be recycled across folds. If actual implementation uses dictionaries/sorting differently, state its real cost, not a preferred theoretical cost.

P07 costs the sum of complete fits/predictions over O outer ×M candidates×I inner folds plus outer/final refits; training sizes vary. The76 original pipeline fits count excludes3 majority baselines; no time claim. Index validation may use O(n) masks per split, but must not erase original IDs. P08 finite probability uses exact integer combinations; avoid overflow by Python integers and stable ratio/log arithmetic for larger supported domains. P13 finite-density reference scans/aggregates history and candidate cards; no comparison to continuous TPE asymptotics. P14 rounds/sorts survivors; evaluator training dominates real use. P10 exhaustive proof examples intentionally trade scalability for transparency and are labeled accordingly. Required helpers appear as full learner files in the index and have no execution on import. Original P03's original import is preserved exactly with its P02 dependency supplied.
